## TL;DR

- 圓環不是畫出來的，是**算出來的**。沒有任何 `stroke` 或 ring 物件：每顆圓只問一個問題，「我離一個半徑隨時間變大的假想圓有多遠」，再用這個距離調自己的亮度。
- 距離用 **grid 單位**量（row/column index），不用 pixel。`hypotheticalRingRadius = normalize(timeSinceHoverStarted, 0, 1000, 0, numOfRows)`：1 秒後半徑剛好等於 row 數，環頂碰到 canvas 頂。
- 亮度是一條 normalize pipeline：noise 值 → 0 到 100 的 lightness → 依 row 往底部壓暗 → 環前 10 格淡入 → 環邊 6 格內亮度加倍。每一步都吃上一步的輸出。
- 漸層要在 canvas 裡用 `rowIndex` 算，不要疊 CSS `linear-gradient()`。因為 glow 是「目前亮度 × 2」，底部亮度接近 0，所以圓環在底部幾乎看不見，越往上越亮，這個效果是免費得到的。
- 每幀 3750 次 `arc` + `fill`，CPU 很吃重。Josh 猜 Clerk 原版用 GLSL shader。跑不動就把 `CELL_SIZE` 調大。

## Spec

- Canvas 裡是一整片小圓組成的 grid，預設全部看不見。
- Hover 時圓出現，亮度跟著 simplex noise 忽明忽暗。
- 開始 hover 的瞬間，從 canvas 底部長出一個擴張的圓環，靠近環邊的圓特別亮。
- 整體有垂直漸層：最上排在 0% 到 100% 亮度之間跳，最底排永遠是 0%。
- 移出 canvas 後，所有圓淡出消失。
- 使用者開了 reduced motion 就不跑這個動畫。

## Build order

Josh 自己說這題是「最終大魔王」，他也卡了很久。他建議先把靜態的 noise 質地做完，再碰 hover，最後才做圓環。

<details>
<summary>Hint 1 — 先做會閃的 noise 質地和垂直漸層</summary>

用兩層 `range().forEach` 排出 grid，做法跟 Circle Noise Grid 練習一樣。

每顆圓丟三個參數給 `simplex3`：水平位置、垂直位置、動畫開始到現在的秒數。回傳值在 -1 到 1 之間，用 `normalize` 轉成 0 到 100 的 HSL lightness。

漸層不要疊 CSS `linear-gradient()`，那樣下一步會綁手綁腳。改成再做一次 `normalize`：輸入是 `rowIndex`（0 到 `numOfRows - 1`），輸出從「這格的 noise 亮度」走到 0。最上排拿到完整亮度，最底排拿到 0。

</details>

<details>
<summary>Hint 2 — 圓環太難，先做一條往上掃的水平線</summary>

Josh 一開始也不是直接做環。他先降低目標：hover 後，圓從底部一排一排往上亮起來。

先算 hover 了多久，再用 `normalize` 把 0 到 1000ms 對應到「目前掃到哪一排」，從最底排走到第 0 排。

接著算這排跟掃描線差幾排。直接比 `rowIndex >= highlightedRowIndex` 會讓每顆圓「啪」一下亮起來。改用 `clampedNormalize(rowDelta, 0, 10, lightness, 0)`：掃描線還在 10 排以外時是 0，越接近越亮；掃描線過去之後差值變負數，被夾回原本的亮度。

覺得腦袋打結很正常。這一題就是 normalize 疊 normalize，靠經驗養出直覺。

</details>

<details>
<summary>Hint 3 — 把水平線換成圓環，再加 glow</summary>

概念一樣，只是比較對象從「row index 和掃描線」換成「這格離圓心多遠和圓環半徑」。

假設 grid 是 30 排、20 欄，環從第 30 排、第 10 欄（底部正中間）長出來。用畢氏定理算每格離這個點幾個 grid 單位，例如第 30 排第 12 欄離 2 格，第 20 排第 10 欄離 10 格。

半徑每幀隨 hover 時間變大。「離圓心的距離」減「半徑」就是這格離圓環多遠，拿它取代上一步的 `rowDelta`。

最後一步是讓環邊特別亮。Josh 只給一句提示：再加一個 normalize。

</details>

## The lightness pipeline

每顆圓每幀的亮度是一串轉換，後一步吃前一步的輸出：

```ts
const simplexVal = simplex3(centerX / 10, centerY / 10, totalTime); // -1 到 1
const simplexLightness = normalize(simplexVal, -1, 1, 0, 100); // 0 到 100
const baseLightness = normalize(rowIndex, 0, numOfRows - 1, simplexLightness, 0); // 往底部壓暗
```

`baseLightness` 這行很巧：`normalize` 的**輸出範圍本身是變數**。每顆圓的 `simplexLightness` 不一樣，所以每顆圓有自己的「頂端亮度」，再依 row 線性壓到 0。第 0 排拿到全部，中間那排拿到一半，最底排是 0。

算完 `baseLightness` 之後分兩條路：hover 中要套圓環，沒 hover 要淡出。兩條路最後都寫進同一個 `lightness`，畫圓只有一個出口：

```ts
ctx.fillStyle = `hsl(0deg 0% ${lightness}%)`;
ctx.arc(centerX, centerY, CIRCLE_RADIUS, 0, Math.PI * 2);
ctx.fill();
```

## Measuring the ring in grid units

```ts
const hypotheticalRingRadius = normalize(timeSinceHoverStarted, 0, RING_GROW_DURATION, 0, numOfRows);

const spawnPoint = {
  x: Math.round(numOfCols / 2),
  y: numOfRows,
};

const deltaX = spawnPoint.x - colIndex;
const deltaY = spawnPoint.y - rowIndex;
const distanceToSpawnPoint = Math.sqrt(deltaX ** 2 + deltaY ** 2);
const distanceToRing = distanceToSpawnPoint - hypotheticalRingRadius;
```

為什麼用 index 不用 pixel：`CELL_SIZE` 水平垂直一樣，所以 grid 單位是等比的，算出來還是正圓。好處是少換算一次，半徑也能直接跟 `numOfRows` 比。

`spawnPoint.y` 是 `numOfRows`，不是 `numOfRows - 1`。最後一排的 index 是 `numOfRows - 1`，所以圓心在最後一排再往下一格，也就是 canvas 底邊外側。

`distanceToRing` 的正負號就是整個效果的開關：

- **正數**：環還沒到這格。
- **0**：環剛好壓在這格上。
- **負數**：環已經掃過去了。

`hypotheticalRingRadius` 用 `normalize` 而不是 `clampedNormalize`，1 秒後半徑還會繼續長。這是必要的：200×300 的 canvas 是 50 欄 75 排，左上角離圓心 `Math.sqrt(25 ** 2 + 75 ** 2)`，大約 79 格，比 75 遠。夾住的話半徑停在 75，兩個上角永遠不會被環掃到。不夾的話，大約 1054ms 時角落也被蓋過。

## Two clampedNormalize calls: fade band and glowing edge

```ts
lightness = clampedNormalize(distanceToRing, 0, 10, baseLightness, 0);

lightness = clampedNormalize(Math.abs(distanceToRing), 0, 6, Math.min(100, lightness * 2), lightness);
```

**第一次：環前的淡入帶。** 距離 10 格以上輸出 0（還沒輪到）。10 格到 0 格之間從 0 漸漸亮到 `baseLightness`。距離變負數時 `clampedNormalize` 把它夾在 `baseLightness`，環掃過的區域就是完整的 noise 畫面。這裡一定要用 clamped 版本：普通 `normalize` 遇到負距離會輸出比 `baseLightness` 更亮的值，環內會越來越白。

**第二次：環邊的 glow。** 輸入改成 `Math.abs(distanceToRing)`，環的內外兩側一起算。剛好在環上的圓拿到兩倍亮度，離環 6 格以上回到原本的亮度。

用 200×300 的 grid 追最上排中間那顆圓（假設 `baseLightness` 是 50）：

| hover 經過 | 離環 | 亮度 |
|---|---|---|
| 800ms | 15 格 | 0 |
| 933ms | 5 格 | 約 29 |
| 1000ms | 0 格 | 100 |
| 1080ms | 環已過去 6 格 | 50 |

因為 glow 是「目前亮度 × 2」，而 `baseLightness` 在底部接近 0，環在底部幾乎是暗的，往上爬才越來越亮。我的理解是，這也是 Hint 1 不建議用 CSS 漸層的原因：漸層放在 canvas 外面，glow 就不知道每格該有多暗。

## Hover-out fades from baseLightness

```ts
} else {
  const timeSinceHoverEnded = now - (hoverChangeTimestamp ?? -Infinity);
  lightness = clampedNormalize(timeSinceHoverEnded, 0, 1000, baseLightness, 0);
}
```

沒 hover 時完全不看圓環，每顆圓在 1000ms 內從 `baseLightness` 淡到 0。Noise 還在跑，所以淡出途中畫面仍然在閃，不是凍結後變暗。

代價是 interrupt。Hover 到一半（環還沒長完）就移出去，第一幀 `timeSinceHoverEnded` 是 0，亮度直接跳到完整的 `baseLightness`。環還沒掃到的圓會閃一下再淡出。在 200×300 的 grid 上假設每格 noise 亮度都是 50，500ms 時移出，3750 顆裡有 1836 顆亮度往上跳超過 5 個百分點。Josh 把這點列在 Extensions。

## simplex3 → createNoise3D

Josh 的 playground 附一份 vendored noisejs：

```js
const { simplex3 } = createNoiseGenerator(1);
```

這份 port 改用已經裝好的 `simplex-noise` 套件：

```ts
const simplex3 = createNoise3D();
```

- **同一個演算法**：兩份都是 Stefan Gustavson 的 3D simplex（`F3 = 1/3`、`G3 = 1/6`、kernel 半徑 0.6、最後乘 32）。
- **輸出範圍一樣**：都是 -1 到 1，所以 `normalize(simplexVal, -1, 1, 0, 100)` 不用改。我在這個 grid 的輸入上各抽 60 萬個樣本：兩邊的 min / max 都是 ±0.979，平均絕對值都約 0.35。`simplexLightness` 約六成落在 30% 到 70% 之間，很少碰到 0 或 100。
- **頻率一樣**：`centerX / 10` 的除數照搬，閃爍顆粒大小相同。
- **差別只有 seed**：`createNoiseGenerator(1)` 用固定 seed，每次載入都是同一個 pattern。`createNoise3D()` 預設用 `Math.random()` 建 permutation table，每次 mount 的 pattern 都不同。

## Gotchas

- **Hint 的程式碼跟解答不一致。** Hint 1 寫的是 `centerX / 2`，文字又說傳 column / row index。解答用 `centerX / 10`，也就是每格差 0.4 個 noise 單位，顆粒細但相鄰格還有關聯。除以 2 的話相鄰格差 2 個單位，幾乎等於 random，會變成電視雪花。我照解答。
- **`Math.min(100, lightness * 2)` 不只是防超過 100。** CSS 本來就會把 lightness 夾在 100%，但這個值是 `clampedNormalize` 的起點。假設目前亮度是 70：不夾的話起點是 140，離環 3 格的圓算出 105（顯示成 100），夾住則是 85。不夾的 glow 會變粗、邊緣變硬。
- **Reduced motion 是每幀檢查，一旦成立 loop 就停。** `draw()` 開頭 `return`，沒排下一個 rAF。圓預設看不見，所以 reduced motion 使用者看到的是空 canvas。如果 hover 中途才打開系統設定，畫面會停在最後一幀，關掉設定也不會重啟，要重新 mount。
- **不需要 deltaTime。** 所有東西都是絕對時間的函數（`totalTime`、`now - hoverChangeTimestamp`），掉幀或背景分頁回來都不會累積誤差，跟 [Simplex Noise](/wham/canvas-animation/simplex-noise) note 同一個性質。
- **效能。** 每幀 3750 次 `beginPath` / `arc` / `fill`，外加 3750 次 `fillStyle` 字串解析。Canvas 放大到 800 寬會變成 1 萬多次。低階機器卡的話，先把 `CELL_SIZE` 從 4 調大。
- **偏離 1：`createNoise3D()` 取代 vendored `noise.vendor.js`。** 不複製 400 行的 vendored 檔，用已安裝的套件。範圍、頻率一樣，只有 seed 不同，細節見上一節。
- **偏離 2：`hoverChangeTimestamp ?? -Infinity`。** Josh 的 `hoverChangeTimestamp` 初始是 `null`，JS 裡 `now - null` 等於 `now`，也就是頁面載入到現在的毫秒數。如果第一幀在載入後 1000ms 內跑，淡出公式會算出非 0 的亮度，grid 會莫名其妙亮一下再淡掉（例如 600ms 時頂排拿到 40% 的 `baseLightness`）。在 Josh 的 playground 裡，每次改 code 都重載 iframe，這個情況很常見。改成 `-Infinity` 代表「從沒 hover 過」，淡出早就結束，所有圓一開始就是 0。
- **偏離 3：hover 分支用 `hoverChangeTimestamp!`。** 純 TypeScript 型別處理。`isHovering` 只會在 `pointerenter` 設好時間戳之後才變 true。
- **偏離 4：React 包裝。** `setupCanvas` 回傳的 `dimensions` 改名成 `canvasDimensions`；`pointerenter` / `pointerleave` 改成具名函式，cleanup 時才能 `removeEventListener`；cleanup 也 `cancelAnimationFrame` 和 `disposeResize`。`checkPrefersReducedMotion` 在 `~/utils/canvas` 沒有，照 Josh 的 `utils.js` 在檔案裡定義一份。
- **偏離 5：外框。** Josh 的 `index.html` 把 canvas 設成 200×300 加 1px outline，`styles.css` 讓整頁黑底。這裡用 inline style 設 canvas 尺寸和 outline，外面包一層 `bg-black` 的 div 取代黑色頁面。

## Extensions

- 不要只有灰階，讓整個效果變成多色。
- 處理 interrupt：環還沒長完就移出時不要閃。可以讓環縮回去，或讓擴張先跑完，再開始淡出。
- 點擊或觸控 canvas 時加第二個效果，例如 cursor 附近的圓短暫變亮。
- 目前圓本身完全不動，動感全靠 noise 和圓環。試試讓圓也移動。
