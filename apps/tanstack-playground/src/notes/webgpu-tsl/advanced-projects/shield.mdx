## TL;DR

- 這一課做一顆能量護盾。表面的六角形一直在變大變小，點一下，附近的六角形撐滿、變亮。整個效果包成 `Shield` class，加進 scene、debug UI、載貼圖都交給用的人。
- 六角形來自一張會無縫重複的貼圖。三個 channel 各存一種資料：`.r` 是到格子邊緣的距離，`.g` 是每格一個亂數，`.b` 分出格子和縫。
- `hexagonsStep.step(hexagonsColor.r)`：`r` 小於等於 `hexagonsStep` 的地方是 1。`hexagonsStep` 從 0 長到 1，六角形就從中心長滿。
- `hexagonsStep` 是 `sin(time + g × 2π)` 再 `remap()` 到 0–1。每格的 `g` 不同，所以每格不同步。
- 花紋是五張灰階 `mul()` 起來：大小、縫、兩極淡出、fresnel、fill。
- impact 存在 `uniformArray(data, 'vec4')`，xyz 是位置，w 是半徑。直接改 JS 那邊的 `Vector4`，每次 render 都會重新上傳。
- shader 用 `Loop()` 走過全部 impact，`max()` 留最強的，得到 `finalImpact`。它再用 `max()` 塞進 `hexagonsStep`、fresnel mask、fill 三個地方。
- 點擊不測三角形，`raycaster.ray.intersectSphere()` 打一顆數學球。拿到的是世界座標，`mesh.worldToLocal()` 轉成 local 之後，impact 才會黏在護盾上。
- 材質是黑色的 `MeshBasicNodeMaterial`，加 `AdditiveBlending`，花紋寫在 `emissiveNode`。`emissiveStrength` 乘上 `strength`（7）之後拿去 `mix()` 兩個顏色，超過 1 的地方被外插到 `colorB` 之外。
- Junction 是給別的 material 用的 node：到護盾中心的距離減掉 `radius` 就是 SDF，交界附近發光。護盾的位置用 `objectPosition(mesh)`，不是 `modelPosition`。

## 為什麼六角形用一張貼圖

```js
const hexagonsColor = texture(this.texture, uv().mul(vec2(6, 4)));
```

課程的貼圖用 Substance Designer 做，三個 channel 各放一種資料：

- `.r`：到格子邊緣的距離。中心 0，邊上 1。它同時決定六角形的大小（下一節）和格子裡的漸層（fill）。
- `.g`：每格一個 0 到 1 的亂數，整格同一個值。拿來錯開每格的時間。
- `.b`：格子裡是 1，縫是 0。它在 shader 裡當 alpha 用，放哪個 channel 都沒差。

用貼圖是為了快。課程最後也說，對 GPU 來說取樣一張貼圖很便宜。一次取樣拿到三種資料，比在 shader 裡算六角形格子省事得多。

貼圖可以無縫重複，所以 `wrapS` / `wrapT` 設成 `RepeatWrapping`，`uv().mul(vec2(6, 4))` 繞球一圈貼 6 次、上下貼 4 次。

demo 沒有用課程的 PNG。`createHexagonsTexture()` 用 JavaScript 自己算一張，channel 的意思照上面。一張貼圖裡有 4 × 4 格，每隔一列錯開半格，列數是偶數，所以邊界接得起來。

貼圖載入放在 `script.js`，用 `loadAsync()` 載好再當參數傳進 `new Shield(hexagonsTexture)`。課程的理由是：你不知道別人怎麼管理素材，就讓他自己載。constructor 的參數叫 `_texture`，避開 TSL 的 `texture()`；它排第一個：貼圖非給不可，`radius` 放後面才能有預設值。

## 為什麼 step() 要反過來寫

```js
const hexagonsStep = max(time.add(hexagonsColor.g.mul(TWO_PI)).sin().remap(-1, 1, 0, 1), finalImpact);
const hexagonsMask = hexagonsStep.step(hexagonsColor.r);
```

TSL 的鏈式寫法 `x.step(edge)` 等於 `step(edge, x)`（three 0.186 `MathNode.js` 的 `stepElement`）。所以：

- `hexagonsColor.r.step(hexagonsStep)`：`r ≥ step` 的地方是 1。白的是格子外圍那一圈。
- `hexagonsStep.step(hexagonsColor.r)`：`r ≤ step` 的地方是 1。白的是從中心長出來的六角形，step 愈大，六角形愈大。

課程先寫前一種，再改成後一種，因為 mask 應該是「要留的地方是白的」。改成 `oneMinus()` 也行。

順序一換，`hexagonsStep` 變成點號左邊那個。寫成 `const hexagonsStep = 0.5` 會出錯，JavaScript 的數字沒有 `.step()`，要寫 `float(0.5)`。換成 `time.sin()` 之後它本來就是 node，問題消失。

step 一路加工：

- `time.sin()`：-1 到 1。負的那一半什麼都看不到，六角形會消失一陣子。
- `.remap(-1, 1, 0, 1)`：映到 0 到 1。後兩個參數預設就是 0 和 1，可以省。
- `time.add(hexagonsColor.g)`：每格錯開一點。但 `g` 只有 0 到 1，sin 一個週期是 2π，所以每格還是差不多同步。
- `hexagonsColor.g.mul(TWO_PI)`：錯開整整一個週期，才真的亂。

## 為什麼是五張灰階相乘

```js
const hexagonsPolarMask = uv().y.sub(0.5).abs().remapClamp(0.35, 0.2);
const hexagonsFresnelMask = max(fresnel.pow(2), finalImpact);
const hexagonsFill = max(hexagonsColor.r, finalImpact);
const hexagons = mul(
  hexagonsMask,
  hexagonsColor.b,
  hexagonsPolarMask,
  hexagonsFresnelMask,
  hexagonsFill
);
```

每一張只管一件事，五張都亮的地方才看得到六角形。`mul()` 一次吃五個參數。

- `hexagonsColor.b`：取樣剛好落在兩格之間時，會混到兩格的 `g`，縫上出現細細的怪線。課程說這是貼圖精度造成的，乘上縫的 mask 把它蓋掉。
- `hexagonsPolarMask`：球的 uv 在兩極擠成一點，六角形拉得很難看。`uv().y.sub(0.5).abs()` 是離赤道多遠，`remapClamp(0.35, 0.2)` 讓它在 0.2 以內維持 1、到 0.35 降到 0。課程提到 triplanar mapping 可以真的解決，但會帶來別的問題，也比較慢。
- `hexagonsFresnelMask`：只在側邊顯示，不管球怎麼轉、鏡頭在哪。`pow(2)` 把中間壓得更暗。
- `hexagonsFill`：格子裡不要一片平，要愈靠邊愈亮，`.r` 剛好就是這個漸層。

fresnel 寫在 `hexagons` 那段之前，因為最後發光那段還要用它一次：

```js
const fresnel = dot(positionViewDirection, normalView).abs().oneMinus();
```

`positionViewDirection` 是 fragment 到鏡頭的方向，`normalView` 是法線，兩個都在 view space，dot 的結果跟 world space 一樣。

`abs()` 不能省。背面的 dot 是負的，`oneMinus()` 之後變成 `1 - (-1) = 2`。課程說，材質一開透明加 `DoubleSide`，背面就會過亮。

## 為什麼 impacts 是 uniformArray + Loop() + max()

```js
// setImpacts()
const data = [];
for (let i = 0; i < this.impacts.count; i++) data.push(new THREE.Vector4(0, 0, 0, 0));
this.impacts.uniforms = uniformArray(data, 'vec4');

// colorNode / emissiveNode
const finalImpact = float(0);
Loop(this.impacts.count, ({ i }) => {
  const impactData = this.impacts.uniforms.element(i);
  const impactDistance = impactData.xyz.distance(positionLocal);
  const impact = impactDistance.div(impactData.w).oneMinus().max(0);
  finalImpact.assign(max(finalImpact, impact));
});
finalImpact.assign(finalImpact.remap(0.4, 0, 1, 0));
```

一個 impact 亮一兩秒，點得快就會同時有好幾個，所以要一整組。`count` 是 5，`index` 指向下一個要寫的位置，寫完加一，到底就回 0。最舊的那個被蓋掉。

一個 `vec4` 塞兩種資料：xyz 是中心，w 是半徑。`uniformArray()` 每次 render 都把 JS 陣列重新上傳，所以 `add()` 只要改 `data[index]` 的四個數字，不用碰 `.value`。

shader 這邊每個 impact 算一個強度：

- `distance(positionLocal)`：中心是 0，往外變大。
- `.div(impactData.w)`：中心 0，走到半徑剛好 1。
- `.oneMinus()`：反過來，中心 1，半徑 0。
- `.max(0)`：半徑外面變負的，壓回 0。

好幾個 impact 重疊時，留最強的。課程先寫 `If(impact.greaterThan(finalImpact), …)`，再改成 `max()`，意思一樣，短很多。

最後的 `remap(0.4, 0, 1, 0)` 就是 `x / 0.4`，沒有 clamp，中心到 2.5。課程說這是故意的，比較亮。`d < 0.6w` 的地方都 ≥ 1，三個 `max()` 碰到就整格撐滿。

`finalImpact` 用 `max()` 塞進三個地方：

- `hexagonsStep`：≥ 1 時 `r ≤ hexagonsStep` 處處成立，六角形長滿。
- fresnel mask：正面中間本來是暗的，impact 附近也亮起來。
- fill：不再只有邊緣亮，整格填滿。

`const finalImpact = float(0)` 再 `assign()`，沒有先 `.toVar()`。three 0.186 照跑，demo 就是這樣寫的，畫面和 Console 都正常。為什麼不用 `.toVar()` 也行，原因沒查。

課程用 GSAP 做半徑的動畫：0.1 秒 `power2.out` 漲到 `radius`，`onComplete` 再用 1 秒 `power2.in` 收回 0。demo 改在 `useFrame` 裡算同樣兩段。GSAP 的 power2 是三次方。

## 為什麼點擊要 intersectSphere() 和 worldToLocal()

```js
raycaster.setFromCamera(mouse, camera);
const sphere = new THREE.Sphere(shield.mesh.position, shield.radius.value);
let intersect = new THREE.Vector3();
intersect = raycaster.ray.intersectSphere(sphere, intersect);
if (intersect) shield.impacts.add(intersect);
```

課程說 `intersectObject()` 一個一個三角形測，比較貴。目標是一顆球，就對數學上的 `Sphere` 測，便宜很多。

`intersectSphere()` 要先給一個 `Vector3` 讓它填，打不到時回傳 `null`，打到就回傳你給的那個。所以兩件事都要做：傳進去，再用回傳值重新指派。不重新指派，沒打到時 `intersect` 留在 `(0, 0, 0)`，等於在護盾中心打了一下。

這裡還有一個課程沒特別提的好處。幾何體半徑是 1，畫出來的半徑 2 是 `positionNode` 在 shader 裡乘的。`intersectObject()` 只認得 CPU 上那顆半徑 1 的三角形。用 `radius.value` 做的 `Sphere` 才跟畫面一致。依據是讀程式，三角形版本沒實測。demo 點球的外緣，impact 亮在游標下，這點實測過。

`intersect` 是世界座標，shader 卻拿 `positionLocal` 比距離。護盾一移動，兩邊就對不上。兩個解法：

- shader 改用 `positionWorld`：能動，但護盾移動時 impact 會停在原地，像掛在空中。
- `this.mesh.worldToLocal(position)` 先轉成 local：impact 跟著護盾走。

課程選後者。demo 讓護盾慢慢自轉，impact 照樣黏在表面上轉，就是這個效果。

## 為什麼是黑色 + AdditiveBlending + emissiveNode

```js
this.material = new THREE.MeshBasicNodeMaterial({
  transparent: true,
  blending: THREE.AdditiveBlending,
  color: 0x000000,
  side: THREE.DoubleSide,
});
```

護盾應該是能量，自己發光。用 `emissiveNode` 而不是 `colorNode`，之後想用 MRT 單獨抓出 emissive 做 bloom 也方便。

`MeshBasicNodeMaterial` 預設是白的，加了 emissive 還是一片白。底色改成黑，再用加法混合，黑色加上去等於沒加，畫面上只剩 emissive。`DoubleSide` 讓背面的六角形也畫出來。

```js
const emissiveStrength = add(hexagons, fresnel.pow(5), lines).mul(this.strength);
const emissive = mix(this.colorA, this.colorB, emissiveStrength).mul(emissiveStrength);
```

- `fresnel.pow(5)`：只剩最外緣一圈，讓整顆球有輪廓。
- `lines`：`positionWorld.y.mul(20).add(time).fract().pow(3)` 是往下流的細橫線，再乘上一個慢慢變化、最大 0.05 的強度。
- `.mul(this.strength)`：放大 7 倍。超過 1 的部分，下一行的 `mix()` 會外插，顏色衝過 `colorB`，bloom 也更明顯。
- `mix(colorA, colorB, emissiveStrength)`：弱的地方偏 `colorA`，強的地方偏 `colorB`。
- `.mul(emissiveStrength)`：弱的地方壓向黑色，加法混合下就是透明。

課程說這個效果很吃 bloom，只給了 threshold 0、強度低。demo 的 strength 0.1 是自己挑的。

## 為什麼 junction 寫在別的 material 上

demo 沒有做這一段，只有文字。

護盾穿過地板時，交界只是硬生生切過去。課程讓交界發光，做法是在 `Shield` 裡準備一個 node，給別的 material 加到自己的 emissive 上：

```js
setJunctionNode() {
  const center = objectPosition(this.mesh);
  this.junctionNode = Fn(() => {
    const sdf = positionWorld.distance(center).sub(this.radius);
    const mask = sdf.negate().step(0);
    const strength = sdf.remapClamp(0, -0.2, 1, 0).mul(mask).pow(3).mul(this.strength);
    const _color = mix(this.colorA, this.colorB, strength).mul(strength);
    return _color;
  })();
}

// script.js
mesh.material.emissiveNode = materialEmissive.add(shield.junctionNode);
```

- `sdf`：到護盾中心的距離減掉半徑。交界上是 0，外面是正的，裡面是負的。
- `remapClamp(0, -0.2, 1, 0)`：交界是 1，往裡走 0.2 降到 0。不 clamp 的話，更裡面會一路變負。
- `mask`：外面原本也是 1，要切成 0。`sdf.negate().step(0)` 只留裡面。
- 顏色照護盾的做法：`mix()` 再乘回強度。

護盾中心不能用 `modelPosition`。這個 node 掛在地板上，`modelPosition` 會是地板的位置。`objectPosition(this.mesh)` 指定要護盾那一個 object，而且是世界座標，護盾放在別的 group 裡也對。

`materialEmissive.add(…)` 保留 material 原本的 emissive，不會整個蓋掉。哪個物件要有交界效果，就自己加這一行，所以可以挑。

課程也列了別的做法：後製用 MRT，或之後才會教的 backdrop。

## 用例

- **能量護盾、力場、全息介面**：一張存資料的貼圖加上幾張 mask 相乘，比在 shader 裡算格子便宜。
- **一張貼圖存好幾種資料**：距離、ID、alpha 分開放在 r、g、b。
- **大量物件不同步地動**：`sin(time + id × 2π)`，`id` 從貼圖或 attribute 拿。
- **形狀從中心長大**：`threshold.step(distance)`，threshold 從 0 拉到 1。
- **受擊、點擊、腳印這類短暫效果**：`uniformArray` 當 ring buffer，shader 用 `Loop()` 取 `max()`。
- **事件要黏在會動的物件上**：存 local 座標，`worldToLocal()` 轉過去。
- **球形物件的點擊判定**：`ray.intersectSphere()`，不測三角形。
- **發光又透明的東西**：黑底色 + `AdditiveBlending` + `emissiveNode`。
- **兩個物件的交界發光**：SDF 加 `remapClamp()`，做成 node 讓別的 material 加上去。

## Gotchas

- **`x.step(edge)` 是 `step(edge, x)`**。順序寫反，mask 剛好黑白顛倒。
- **`const hexagonsStep = 0.5` 不能 `.step()`**。JavaScript 數字沒有這個方法，要 `float(0.5)`。
- **`sin()` 是 -1 到 1**。直接當 step，六角形有一半的時間不見，要先 `remap()`。
- **`g` 只有 0 到 1，要乘 `TWO_PI`**，不然每格還是幾乎同步。
- **縫上的細線**是取樣混到兩格的值，乘上 `.b` 蓋掉。
- **fresnel 要先 `abs()` 再 `oneMinus()`**。不然背面是 2，開了 `DoubleSide` 會過亮。
- **impact 是世界座標，shader 比的是 local**。要先 `worldToLocal()`。它會直接改傳進去的 `Vector3`。
- **`intersectSphere()` 要傳 `Vector3`，也要接回傳值**。沒打到是 `null`，不接的話 `(0, 0, 0)` 會被當成一個 impact。
- **`remap()` 不 clamp**。`finalImpact` 中心是 2.5。要限制範圍就用 `remapClamp()`。
- **`modelPosition` 是「被畫的那個物件」**。junction node 掛在地板上，要護盾的位置得用 `objectPosition(mesh)`。
- **`strength` 7 加上 R3F 預設的 ACES tone mapping，整顆球偏粉紅**。demo 實測：strength 拉到 1–2 才看得到 `colorA` 的藍。課程 starter 用哪種 tone mapping 沒對照。
- **DataTexture 預設是 `NearestFilter`、沒有 mipmap**。`TextureLoader` 載的 PNG 預設是 linear 加 mipmap，demo 自己做的貼圖手動設成一樣。
- **R3F 寫法**：`@types/three` 0.186 只在 `MeshStandardNodeMaterial` 宣告了 `emissiveNode`，three 本身的 `NodeMaterial` 對所有 material 都會讀。demo 用 spread 傳進 `<meshBasicNodeMaterial>`，繞過 JSX 的型別檢查。
- **R3F 寫法**：`uniformArray<'vec4'>(…)` 的型別參數只給 TypeScript 看。不寫的話，`element(i)` 上沒有 `.xyz` 和 `.w`。
- **R3F 寫法**：課程的 canvas 佔滿視窗，NDC 用 `sizes.width`。demo 的 canvas 只是頁面的一塊，要用 `getBoundingClientRect()` 扣掉位置。
- **R3F 寫法**：pointerdown 掛在 `gl.domElement` 上自己做 raycast，跟課程一樣，不用 R3F 的 `onPointerDown`。R3F 的事件測的是 mesh 的三角形，也就是半徑 1 的那顆（從程式推的，沒實測）。
