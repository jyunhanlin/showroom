## TL;DR

- 這一課用 TSL 重做 Three.js Journey 舊的 Coffee Smoke。一片細分過的平面放在杯口，vertex 讓它扭、讓它飄，fragment 決定哪裡看得到。
- 動頂點就掛 `positionNode`，內容包在 `Fn()` 裡。`Fn(() => …)()` 最後那對括號是呼叫，少了它煙就不見了。
- `const newPosition = positionLocal` 不是複製。`positionLocal` 在 vertex shader 裡本來就是一個變數，`assign()` / `addAssign()` 直接改它。
- 換成 `positionGeometry` 會編譯失敗。它是 attribute，也就是 `main()` 的參數，WGSL 不讓你寫。要用它就先 `.toVar()`。
- Twist：`rotate(newPosition.xz, angle)` 繞 y 軸轉。角度跟著高度和時間變，再過 `sin()` 讓它來回擺。
- Wind：`mx_noise_vec3()` 一次給三個 noise，剛好當一個方向。乘上 `uv().y.mul(5)`，杯口不動，愈高飄愈遠。
- 扭轉、風、煙的花紋都是「座標減 `time`」，所以全部往上走。寫成 `add(time)` 就往下。
- 透明度掛在 `opacityNode`，不包 `Fn()`，因為沒有要 assign 的東西。
- 煙的濃淡是 `mx_noise_float(uv)`，輪廓是四個邊各一條斜坡、`min()` 取最小。兩張灰階相乘。
- `min()`、`max()`、`add()`、`mul()` 可以一次吃兩個以上的參數。
- `clamp(0, 1)` 在 `opacityNode` 上只是保險：three 0.186 輸出前會先 `max(0)`。改寫在 `outputNode` 就沒這層保護，負的 alpha 會把畫面往煙的反色推。

## 為什麼 positionLocal 可以直接改

課程第一步是確認 `positionNode` 接得上：

```js
material.positionNode = Fn(() => {
  const newPosition = positionLocal;
  newPosition.x.addAssign(2);
  return newPosition;
})();
```

這裡有個矛盾。Node Functions 那課說，要被 `addAssign()` 改的東西得先 `.toVar()`，這裡卻沒有，照樣能動。換成 `positionGeometry` 反而壞掉。

答案在生成的 shader 裡。這是 demo 用 `renderer.debug.getShaderAsync()` 撈出來的 vertex shader 開頭（節錄）：

```wgsl
fn main( @location( 0 ) position : vec3<f32>,
	@location( 1 ) uv : vec2<f32> ) -> VaryingsStruct {
	positionLocal = position;
	nodeVar0 = ( sin( ( ( positionLocal.y * 0.3 ) - ( render.nodeUniform0 * 0.2 ) ) ) * 3.0 );
	// …
	positionLocal.x = nodeVar3[ 0 ];
	positionLocal.z = nodeVar3[ 1 ];
	positionLocal = ( positionLocal + ( … mx_perlin_noise_vec3_1( … ) … ) );
	positionLocal = positionLocal;
```

- `position` 是 attribute，在 WGSL 裡是 `main()` 的參數。參數不能寫，所以對 `positionGeometry` 做 assign 會編譯失敗。
- `positionLocal` 是 three 另外宣告的變數，第一行就把 `position` 抄進去。three 自己的 displacement map 也是對它 `addAssign()`（`NodeMaterial.js` 第 788 行）。它本來就是拿來改的。
- 所以 `const newPosition = positionLocal` 只是替同一個變數多取一個 JavaScript 名字。twist 那一步直接寫進 `positionLocal.x` 和 `positionLocal.z`。
- 最後那行 `positionLocal = positionLocal;` 是 NodeMaterial 自己加的 `positionLocal.assign(positionNode)`（第 806 行）。`positionNode` 回傳的就是 `positionLocal` 本身，所以自己指派給自己。

改成 `positionGeometry.toVar()`，shader 會多一行 `nodeVar0 = position;`。改的是複本，最後才 `positionLocal = nodeVar0`。兩個版本畫面一樣。

Node Functions 那課沒有說錯。那一課的 `line` 是一條算式，要 `.toVar()` 才變成變數；`positionLocal` 一開始就是變數。

`xz.assign()` 被拆成兩行，是因為 WGSL 不能對 `.xz` 這種多個分量一起賦值。TSL 會自己拆，你不用管。

## 為什麼要包 Fn()，而且要呼叫它

`assign()` 和 `addAssign()` 要掛在 `Fn()` 的 stack 上，這在 Node Functions 講過。這一課多說了一個好處：`Fn()` 的 body 是一個 JavaScript scope，`angle`、`wind` 這些名字不會跟外面撞。

`Fn(() => { … })` 只是宣告，後面那對 `()` 才是呼叫，呼叫完才得到可以掛上去的 node。demo 拿掉那對括號試過：煙整片消失，Console 印出 `THREE.TSL: "Fn()" was declared but not invoked. Try calling it like "Fn()( ...params )".`

透明度那一段沒有包 `Fn()`，因為它沒有要 assign 的東西，只是把 node 串起來。代價是少了那層 scope，變數名得自己顧好，別叫 `color`、`time` 這種 TSL 已經用掉的名字。

## 為什麼扭轉要過 sin()

```js
const angle = positionLocal.y
  .mul(0.3)
  .sub(time.mul(0.2))
  .sin()
  .mul(3);
newPosition.xz.assign(rotate(newPosition.xz, angle));
```

繞 y 軸轉，動到的只有 x 和 z。`rotate()` 收 vec2 就是 2D 旋轉，`xz.assign()` 直接寫回那兩格，y 不動。Math 那課用 `vec3(newXZ.x, positionLocal.y, newXZ.y)` 手動重組，這裡省掉了。

角度一步步加上去：

- 只有 `positionLocal.y`：愈高轉愈多，整條煙是一根規規矩矩的螺絲。
- 減掉 `time`：螺絲開始動，下一節講為什麼是減。
- 過 `sin()`：角度在 -1 到 1 之間來回。煙一段往這邊扭、一段往那邊扭，不再像螺絲。
- `mul(3)`：擺幅放大到正負 3 弧度，快轉半圈。
- `mul(0.3)`：平面高 6，`0.3 × 6 = 1.8`，整條煙只走不到三分之一個 sin 週期。這個數愈大，扭來扭去的段數愈多。

串太長不好讀就斷行。這還是 JavaScript，斷在哪都行。

## 為什麼三個地方都減 time

```js
positionLocal.y.mul(0.3).sub(time.mul(0.2));              // Twist
newPosition.sub(vec3(0, time.mul(0.3), 0)).mul(0.4);      // Wind
uv().mul(vec2(3, 2)).sub(vec2(0, time.mul(0.1)));         // Smoke
```

三個花紋都是「拿座標去查一個函式」。把查的位置改成 `y - t`：t 秒後，原本在 `y` 的樣子出現在 `y + t`。所以座標減 `time`，花紋往上走；加 `time`，往下走。

課程第一次寫的是 `add(time)`，一跑發現煙往下扭，才改成 `sub()`，原因就是這個。煙是往上冒的，三個地方都減。

減在哪一軸，就往哪一軸走。風和煙都用 `vec3(0, t, 0)` / `vec2(0, t)` 只減 y，花紋只會上升，不會橫著漂。

速度要把兩個係數一起看。扭轉是 `0.3y − 0.2t`，花紋每秒爬 0.2 ÷ 0.3，約 0.67。風是先減再乘 0.4，每秒爬 0.3。煙的濃淡在 uv 裡每秒爬 0.1 ÷ 2 = 0.05，平面高 6，換算也是每秒 0.3。風和濃淡一樣快，扭轉快一倍多。

## 為什麼風力要乘 uv().y

```js
const windCoordinates = newPosition.sub(vec3(0, time.mul(0.3), 0)).mul(0.4);
const windStrength = uv().y.mul(5);
const wind = mx_noise_vec3(windCoordinates).mul(windStrength);
newPosition.addAssign(wind);
```

`mx_noise_vec3()` 回傳 vec3，三個分量各是一個 Perlin noise，湊起來就是一個方向。相鄰的頂點拿到相近的方向，所以整條煙是順順地彎，不會碎掉。

`mul(0.4)` 把座標縮小。同一段高度裡 noise 變得比較慢，煙彎的次數變少，每一彎拉得比較長。推多遠不歸它管，那是下一行的事。課程習慣用乘的，`div(2.5)` 效果一樣。

`windStrength` 決定每個頂點被推多遠。平面的 `uv().y` 在杯口是 0、頂端是 1，乘 5 之後杯口不動，頂端被推最遠。所以煙像從杯子裡冒出來，不是整條飄在空中。

改用 `positionLocal.y` 也能做到，但它在這裡是 0 到 6，跟著 geometry 的尺寸走。平面拉高，風力也跟著變。`uv().y` 不管平面多高都是 0 到 1，`5` 永遠就是頂端的倍數。

`windCoordinates` 讀的是已經扭過的 `newPosition`。上一節說過它們是同一個變數，twist 寫進去的結果，wind 這裡讀得到。

## 為什麼透明度是兩張圖相乘

```js
const smoke = mx_noise_float(
  uv()
    .mul(vec2(3, 2))
    .sub(vec2(0, time.mul(0.1)))
);
const edgeFade = min(
  uv().y.mul(10),           // Bottom
  uv().y.oneMinus(),        // Top
  uv().x.mul(5),            // Left
  uv().x.oneMinus().mul(5)  // Right
);
material.opacityNode = mul(smoke, edgeFade).clamp(0, 1);
```

`smoke` 管煙裡面的濃淡。平面寬 1.5、高 6，uv 卻都是 0 到 1。`vec2(3, 2)` 放到平面上，橫向每單位 2 格、縱向每單位 1/3 格，花紋被拉成一條條直的，像往上飄的煙絲。

`edgeFade` 管煙的輪廓。每個邊一條斜坡，從邊上的 0 爬到 1：

- `uv().y.mul(10)`：底邊。高度走到 1/10 就爬到 1，所以底部淡出得很快。
- `uv().y.oneMinus()`：頂邊。沒乘東西，一路從底淡到頂。`oneMinus()` 就是 `float(1).sub(x)`，但少打一個 `float()`。
- `uv().x.mul(5)` 和 `uv().x.oneMinus().mul(5)`：左右各 1/5 寬。

`min()` 取四條裡最小的，意思是「離哪個邊最近，就聽那個邊的」。四條斜坡在角落交會，會留下一道斜的接縫，像畫框的斜角。單獨看 `edgeFade` 很明顯，乘上 `smoke` 就看不出來。

`mul(smoke, edgeFade)` 是兩張灰階相乘，兩邊都亮的地方才看得到煙。

`opacityNode` 在 NodeMaterial 裡是 `diffuseColor.a.mul(opacityNode)`（第 866 行），乘在 material 原本的 `opacity` 上，所以一定要開 `transparent`。給 `0.5` 這種純數字也行，three 會先包一層 `float()`（第 865 行）。

## 為什麼 clamp(0, 1) 在這裡看起來沒差

`mx_noise_float()` 的範圍是 -1 到 1，相乘之後大約一半是負的。課程加 `clamp(0, 1)` 當保險。

但在 three 0.186 拿掉它，畫面一模一樣。原因在 `NodeMaterial.js` 第 537 行：

```js
// force unsigned floats - useful for RenderTargets
const basicOutput = vec4( outgoingLightNode, diffuseColor.a ).max( 0 );
```

輸出前 three 把顏色和 alpha 一起 `max(0)`，負的 alpha 被壓成 0。demo 撈出來的 fragment shader 最後就是 `max( vec4<f32>( outgoingLight, DiffuseColor.w ), vec4<f32>( 0.0 ) )`。

這層保護只在正常流程裡。課程提過 alpha 也能寫在 `outputNode` 的第四格，但 `outputNode` 會整個取代這個結果。demo 換成白煙、中灰背景試過：

```js
material.outputNode = vec4(1, 1, 1, mul(smoke, edgeFade));
```

煙裡出現一條條黑色的折痕。加回 `.clamp(0, 1)` 就乾淨了。

負的 alpha 為什麼是黑的：混合公式是 `src × a + dst × (1 − a)`。`a` 是負的，就是把背景放大，再減掉一點煙的顏色，畫面被往煙的反方向推。白煙的反方向就是暗。輸出要轉 sRGB 時（預設就是），WebGPURenderer 先畫進 half float 的 buffer，負數不會被硬體擋掉，最後就留在畫面上。

## 用例

- **從某處冒出來的東西**（煙、蒸氣、火焰、水草）：位移乘上 `uv().y`，根部固定，尾巴自由。
- **整條在原地扭**：`newPosition.xz.assign(rotate(newPosition.xz, angle))`，角度跟著高度變。
- **自然的擺動**：角度或位移過 `sin()` 或 noise，不要線性一路加上去。
- **花紋往某個方向流**：座標減 `time`，減哪一軸就往哪一軸的正方向走。
- **每個頂點一個隨機方向**：`mx_noise_vec3(position)`，相鄰的頂點方向相近。
- **四邊淡出的平面**（煙、光束、雲、光暈）：`min()` 四條斜坡，乘的數決定淡出帶多寬。
- **兩個條件都成立才顯示**：兩張灰階 `mul()`。
- **只想改透明度**：用 `opacityNode`，比塞進 `outputNode` 的第四格好讀，負數也有人擋。
- **看頂點怎麼動**：material 先開 `wireframe`，形狀對了再關掉調透明度。課程就是這樣做的。

## Gotchas

- **`positionGeometry` 不能直接 assign**。WGSL 回 `cannot assign to value of type 'f32'`，還附一句 `parameters are immutable`。煙整片消失，杯子照畫。要用它就 `.toVar()`。這是在 demo 裡實際換過看到的。
- **`const newPosition = positionLocal` 不是複本**。assign 之後再讀 `positionLocal`，拿到的是改過的值。要原始位置就讀 `positionGeometry`，attribute 不會被改。
- **`Fn(() => …)` 要呼叫**。少了結尾的 `()`，Console 印 `THREE.TSL: "Fn()" was declared but not invoked.`，煙消失。
- **`add(time)` 是往下**。要往上就 `sub()`。
- **`opacityNode` 要配 `transparent`**。R3F 寫成 `<meshBasicNodeMaterial transparent />`。
- **扭過去會露出背面**。demo 的 material 設了 `side={DoubleSide}`，不然轉到背面那段會不見。
- **`depthWrite={false}`**。原版 Coffee Smoke 課程說，從某些角度看，平面會寫進深度、擋住自己後面的部分。demo 照做。在 demo 的角度拿掉它看不出差別，所以這條的依據是課程，不是實測。
- **`clamp()` 在 `opacityNode` 上是保險，在 `outputNode` 上是必要**。three 0.186 只在正常流程 `max(0)`。拿掉 clamp 又改用 `outputNode`，白煙在中灰背景上出現黑色折痕，是實際跑過的。
- **`min()` 會在角落留下斜接縫**。單獨預覽 `edgeFade` 時不是 bug，乘上 `smoke` 就不見了。
- **noise 很貴**。vertex 這邊只有 17 × 65 個頂點，fragment 那邊是每個像素一次 Perlin noise。課程建議之後改用 noise 貼圖。
- **R3F 寫法**：整張 graph 在 module scope 建一次，課程的 `5` 換成 `uniform()`，拉 slider 只改數字，不重編 shader。
- **R3F 的 `<Canvas>` 預設開 ACES tone mapping**，`0x7e583a` 會被洗淡。demo 加了 `flat`，關掉 tone mapping。
- **改 demo 存檔（HMR）之後 slider 可能沒反應**，重新整理就好。推測是 module 重跑建了新的 uniform，material 卻還拿著舊的 graph（原因未查證）。只影響開發時。
