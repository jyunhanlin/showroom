## TL;DR

- `materialColor`、`positionWorld`、`uv()` 這些都是 three.js 幫你準備好的。這一課講怎麼塞**自己的**資料。
- **uniform**：JS 這端建、shader 那端讀，整批頂點同一個值，vertex 和 fragment 兩個 stage 都能用。
- **attribute**：每個頂點各自一份，只存在於 vertex stage，要給 fragment 就得經過 varying，拿到的是內插後的值。
- 幾乎所有事都繞著 `uniform()` 一個 node 轉：`const frequency = uniform(2)`，之後 JS 改 `frequency.value`。
- 改 `.value` 只是換一個上傳的數字，**shader 不重編**。這是 uniform 存在的全部理由。
- 型別很寬：`uniform(vec2(2, 0.25))`、`uniform(color('crimson'))`、bool、vec3、vec4、矩陣都收。
- node 和 three.js class 二選一：`uniform(new THREE.Vector2(2, 0.25))` 跟 `uniform(vec2(2, 0.25))` 得到的是同一個東西。
- 相關的值包成一個 vec2 比開兩個 uniform 好：`frequencies.x` 管密度、`frequencies.y` 管速度，tweak 就改 `frequencies.value.x`。
- 一整組值用 `uniformArray([...])` 一次上傳，再用 `colors.element(index)` 取。index 會被自動轉成 int（順便 floor）。
- 變數叫 `_color` 不是龜毛：`color` 是 TSL 自己的 node 名，同名會蓋掉。
- attribute 的老路：`new Float32Array(count)` → `new THREE.BufferAttribute(array, 1)` → `geometry.setAttribute('random', buf)` → `attribute('random')`。
- 捷徑是連 geometry 都不用碰：`bufferAttribute(randomBuffer, 'float')`，TSL 自己把 buffer 接上 shader。
- `colorNode` 收到 float 會自動補成 vec3，所以丟一個 0~1 的數進去就是灰階，不用自己 `vec3()`。

自己的資料只有兩條路進 GPU：uniform 是一個值，整批頂點和整批像素共用；attribute 是一條陣列，每個頂點從裡面領走自己那一格。差別在 ② 這一格看得最清楚——橘色四行完全一樣，藍色四行各不相同。attribute 只活在 vertex stage，要給 fragment 就得走 varying，所以 ③ 拿到的藍色是頂點之間內插出來的漸層，不是原本那四個數字。黃圈的 `frequencies` 就是 demo 的 slider：下面兩塊是同一支 shader、同一張 node graph，只有上傳的數字從 2 變成 8，條紋就從兩圈變成八圈。

## 為什麼一個 uniform() 就夠

先做一個會動的圖樣來玩。用高度當基礎，`fract()` 讓它每滿 1 就歸零，再減掉 `time` 讓它往上跑：

```js
const pattern = positionWorld.y.sub(time).fract();
material.colorNode = pattern;
```

`colorNode` 要 vec3，`pattern` 是 float，TSL 自動補成三個分量，所以直接接就有灰階。

減 `time` 為什麼是往上跑？固定看某一條紋，它滿足 `y - t = 常數`，也就是 `y = 常數 + t`——時間變大，這條紋所在的高度跟著變大。要往下就改成 `add`。

問題是這樣寫死了：條紋多寬、跑多快都改不了。這就是 `uniform()` 的位置：

```js
const frequency = uniform(2);
const pattern = positionWorld.y.mul(frequency).sub(time).fract();
```

之後 JS 這端只要動 `.value`：

```js
gui.add(frequency, 'value', 0, 10, 0.01).name('frequency');
```

注意 tweak 綁的是 `frequency` 的 `'value'` 屬性，不是 `frequency` 本身，所以預設的 label 會是 `value`，得自己 `.name()` 改掉。

重點不在寫法有多短，在**改 `.value` 只是換一個上傳的數字，node graph 一行沒動，shader 不重編**。同樣一件事如果寫成常數，每動一格就得重新編譯一支 shader，畫面會卡到不能用。uniform 存在的理由就是這個。

## 為什麼相關的值要包成一個 vec2

現在想再控制速度。直覺是再開一個 `uniform()`，但更好的做法是把兩個相關的值裝進同一個：

```js
const frequencies = uniform(vec2(2, 0.25));
const pattern = positionWorld.y.mul(frequencies.x).sub(time.mul(frequencies.y)).fract();
```

`.x` 管密度、`.y` 管速度，swizzle 直接取。tweak 那邊改成綁 `frequencies.value` 的 `x` 和 `y`：

```js
gui.add(frequencies.value, 'x', 0, 10, 0.01).name('positionFrequency');
gui.add(frequencies.value, 'y', 0, 10, 0.01).name('timeFrequency');
```

顏色也一樣收：

```js
const _color = uniform(color('crimson'));
material.colorNode = _color.mul(pattern);
```

變數名前面那條底線不是風格問題。`color` 是 TSL 自己的 node 名，你 import 進來了，再宣告一個同名的 `const color` 就把它蓋掉，後面所有用到 `color()` 的地方一起壞。課程用 `_color` 繞過去，這比想一個「更好的名字」省事。

還有一件容易漏掉的事：**node 和 three.js 的 class 可以互換**。

```js
const frequencies = uniform(new THREE.Vector2(2, 0.25));
const _color = uniform(new THREE.Color('crimson'));
```

不是「也能用」，是**完全同一件事**。`uniform()` 看到參數是 node，會把裡面的常數值挖出來，最後存進 `UniformNode` 的還是那個 `Vector2` / `Color`（three.js `src/nodes/core/UniformNode.js` 的 `uniform()` 就寫在那裡）。所以 `.value` 一定是個 three.js 物件，`gui.addColor(_color, 'value')` 才會動。要在 JS 這端反覆改值的，直接寫 class 版本比較順手。

`bool()`、`vec3()`、`vec4()`、各種矩陣也都收，型別這一塊不用擔心。

## 為什麼有 uniformArray 和 element()

現在要的不是漸層，是幾條分明的色帶，而且顏色要從 JS 給。開五個 `uniform()` 當然可以，但那是五個 uniform、五個 tweak、五個變數名。

`uniformArray()` 一次上傳一整組：

```js
const colors = uniformArray([
  new THREE.Color(0x0b5d79),
  new THREE.Color(0x5ed6c2),
  new THREE.Color(0xfeedaa),
  new THREE.Color(0xfc8f74),
  new THREE.Color(0xcf2c65),
]);
```

取的時候要一個 0 到 4 的 index。手上的 `pattern` 是 0 到 1，乘上長度再往下取整就是了：

```js
const pattern = positionWorld.y
  .mul(frequencies.x)
  .sub(time.mul(frequencies.y))
  .fract()
  .mul(colors.array.length)
  .floor()
  .toInt();

material.colorNode = colors.element(pattern);
```

`floor()` 和 `toInt()` 其實可以省——`element()` 會把參數轉成 `int()`，轉的過程順便就 floor 了。寫出來只是讓意圖明白，不寫也不會錯。

`colors.array.length` 比硬寫 `5` 好，但別誤會它是活的：**這一行只在建 node graph 的當下讀一次**。之後你往 `colors.array` 裡加第六個顏色，`mul()` 裡那個 5 不會自己變成 6，畫面上就是最後一個顏色永遠取不到。

## 為什麼 attribute 可以不掛在 geometry 上

attribute 是另一條路：每個頂點一份。地板雖然是平的，但它有細分，所以有很多頂點可以塞東西。

TSL 之前的老路完全沒變：

```js
const count = geometry.attributes.position.count;
const randomArray = new Float32Array(count);
for (let i = 0; i < count; i++) randomArray[i] = Math.random();

const randomBuffer = new THREE.BufferAttribute(randomArray, 1);
geometry.setAttribute('random', randomBuffer);
```

頂點數從現成的 attribute 借（`position` 一定有），`BufferAttribute` 的第二個參數 `1` 是每個頂點佔幾格。掛好之後用 `attribute()` 按名字拿：

```js
const random = attribute('random');
material.colorNode = random;
```

一樣靠自動轉型變成 vec3，所以看到的是灰階的雜點。

但這裡多繞了一圈：buffer 掛在 geometry 上、shader 再按名字去找。TSL 提供的捷徑是把中間那一步整段拿掉——

```js
const random = bufferAttribute(randomBuffer, 'float');
material.colorNode = random;
```

`geometry.setAttribute()` 不用了，名字也不用取了。TSL 拿到 buffer 自己去接 shader（`BufferAttributeNode.setup()` 看到參數是 `BufferAttribute` 就取它的 `.array` 自己包一份）。少一個字串常數要對，就少一個地方會打錯。

代價是這個 buffer 不再屬於任何 geometry，所以**沒有人幫你檢查長度**。陣列比頂點少，多出來的頂點就讀到別人的資料；多了就是白算。`PlaneGeometry(6, 6, 24, 24)` 的頂點數是 `25 × 25`，不是 `24 × 24`——邊界那一排也是頂點。

還有一件圖上畫的事：`colorNode` 是 fragment stage 的東西，而 attribute 只到 vertex stage。中間那一段 varying 是 TSL 自動接的，所以畫面上看到的是頂點之間**內插後**的漸層，不是你塞進去的那些數字本身。想看到原值，得讓每個 fragment 剛好對上一個頂點，那基本上做不到。

## 用例

- **值要能在執行時調**：`uniform()`，然後只改 `.value`。寫死成常數等於每次調整都重編 shader。
- **要接 GUI**：tweak 綁的是 `.value`，記得 `.name()` 換掉預設 label。
- **兩個值本來就相關**：包成一個 `uniform(vec2(...))`，用 `.x` / `.y` 取，別開兩個。
- **要在 JS 這端反覆改**：`uniform(new THREE.Vector2(...))` / `uniform(new THREE.Color(...))`，`.value` 直接是物件，`.set()` 和 `addColor()` 都能用。
- **一整組值（調色盤、關鍵點、偏移量）**：`uniformArray([...])` 配 `element(index)`。
- **0~1 的值要當 index**：`.mul(array.length).floor().toInt()`，長度用 `array.length` 不要硬寫。
- **每個頂點要一份自己的隨機值**：`Float32Array(count)` → `BufferAttribute` → `bufferAttribute(buf, 'float')`。
- **buffer 之後還要給別人用（另一個 material、匯出、之後要更新）**：那就走 `geometry.setAttribute()` + `attribute('名字')`，捷徑塞進去的 buffer 只有那一支 shader 看得到。
- **想快速看一個 0~1 的中間值**：直接丟給 `colorNode`，自動轉型會幫你變灰階。

## Gotchas

- **`const color = ...` 會蓋掉 TSL 的 `color()` node**。課程的 `_color` 是為了這個。同類的還有 `time`、`uv`、`texture`、`mix`，都是很好用的變數名，也都是 node 名。
- **改 `.value` 不重編 shader，改 node graph 會**。slider 走 uniform，選項切換才換 node，這條線劃錯就會卡。
- **tweak 要綁 `.value`，不是 uniform 本身**。而且預設 label 就叫 `value`，兩個 uniform 放一起會看不出誰是誰。
- **`uniform(vec2(...))` 和 `uniform(new THREE.Vector2(...))` 是同一個東西**，不是兩種選擇。`uniform()` 收到 node 會把常數值挖出來，`.value` 最後都是 three.js 物件。
- **`colors.array.length` 只在建 graph 時讀一次**。之後改陣列長度，`mul()` 裡的數字不會跟著變，最後幾個顏色就永遠取不到。
- **`element()` 的 index 會被轉成 int**。轉的時候順便 floor，所以 `floor().toInt()` 是寫給人看的，不是必要的。
- **`uniformArray` 的元素在 GPU 上會被 padding 對齊**（`UniformArrayNode` 自己算了一個 `paddedType`）。所以它佔的記憶體不等於 `length × 元素大小`，塞幾千個之前先想一下。
- **attribute buffer 的長度沒人幫你檢查**。走 `bufferAttribute()` 捷徑時它跟 geometry 完全脫鉤，長度不對不會報錯，只會畫出怪東西。
- **`PlaneGeometry(w, h, 24, 24)` 有 25 × 25 個頂點**。用 `geometry.attributes.position.count` 拿最保險，別自己乘。
- **`bufferAttribute()` 的第二個參數不要省**。node 的型別只能從它得知——這時候還沒有 attribute 可以推。
- **fragment stage 拿到的 attribute 是內插後的值**。畫面上看到的漸層不是你塞進去的數字，中間那一段 varying 是 TSL 自動接的。
- **attribute 只在 vertex stage 存在**。要在 fragment 做逐頂點的判斷（例如「這個頂點屬於第幾群」）會被內插毀掉，那種需求得改用別的做法。
- **R3F 寫法**：換 `colorNode`（三個按鈕、地板的打勾）等於換一支 shader，demo 用 `key` 讓 material 重新掛載。兩個 slider 和顏色不能這樣做，它們走 `uniform()`，`onChange` 裡直接改 `.value.x` / `.value.y` / `.value.set()`，material 不重掛、shader 不重編。`randomBuffer` 在 module scope 就建好，因為它的長度綁死在 `<planeGeometry>` 的細分數上，兩邊得一起改。
