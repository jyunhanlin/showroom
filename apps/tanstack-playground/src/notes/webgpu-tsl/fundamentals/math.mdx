## TL;DR

- 大部分 math node 兩種寫法都行：`add(a, b)` 或 `a.add(b)`。但 JS 數字不能當鏈的起點，`0.25.add(0.5)` 不是合法的 JavaScript。
- 型別轉換自動做，方向卻**看第一個參數**：`int(1).add(float(0.3))` 得到 1，`float(0.3).add(int(1))` 得到 1.3。
- `PI`、`TWO_PI`、`HALF_PI`、`EPSILON`、`INFINITY` 是內建常數 node，不花成本。除法一律 `.div(max(x, EPSILON))`。
- `time` 是「開始 render 到現在的秒數」，自己會更新。不用宣告 uniform，也不用在 tick 裡加。
- `sin()` 回 [-1, 1]。要 [0, 1] 就 `.mul(0.5).add(0.5)`，或者一步到位的 `.remap(-1, 1, 0, 1)`。
- `hash()` 吃一個數，`rand()` 吃一個 vec2。兩個都回 0~1，但內部是兩套完全不同的演算法。
- `rand(uv())` 每個 fragment 都不一樣會很吵；`rand(uv().mul(100).floor())` 先切格才穩。
- Perlin 那一家掛在 `mx_` 前綴底下（materialX）。`mx_noise_float()` 收 vec2 也收 vec3，還有輸出三維的 `mx_noise_vec3()`。
- 扭曲的關鍵在 `angle = time.add(positionLocal.y).sin()`：`time` 讓它動，`positionLocal.y` 讓每個高度轉不同角度。

## 為什麼鏈的第一個 node 決定型別

`add()`、`sub()`、`mul()`、`div()` 這些從第一課用到現在。它們有兩種等價寫法：

```js
const foo = float(0.25);
const bar = float(0.5).add(foo);
const bar2 = add(float(0.5), foo); // 同一件事
```

JS 數字可以當參數，但不能當鏈的起點：

```js
const bar = add(0.25, 0.5); // 可以
const bar = 0.25.add(0.5); // 這根本不是合法的 JavaScript
```

有些 node 吃兩個以上的參數：

```js
const bar = add(0.25, 0.35, 0.4);
```

型別轉換自動做，vector 乘 float 不用自己配合維度：

```js
const foo = vec3(0.25, 0.25, 0.25);
const bar = foo.mul(4);
```

方便歸方便，**方向是看第一個參數決定的**，這裡有坑：

```js
const bar = int(1).add(float(0.3)); // 1（整數）
const bar2 = float(0.3).add(int(1)); // 1.3（浮點數）
```

第一個是 int，第二個參數就被轉成 int，`0.3` 直接被截掉。反過來寫才是你要的。前一課的 Editor 就是驗證這種事最快的地方——貼進去，看生成的 shader 有沒有多一次轉型。

還有很多：`pow()`、`mod()`、`step()`、`min()`、`max()`、`cos()`、`clamp()`、`remap()`……不用背，但值得把清單掃一遍，知道有什麼可以用。清單在 three.js wiki 的 [Three.js Shading Language](https://github.com/mrdoob/three.js/wiki/Three.js-Shading-Language) 頁面。

## 為什麼用 PI 而不是 Math.PI

TSL 內建了常用的數學常數：`PI`、`TWO_PI`、`HALF_PI`、`EPSILON`、`INFINITY`。import 進來就能用，不花成本：

```js
const oppositeAngle = angle.add(PI);
```

寫 `angle.add(Math.PI)` 也會動——JS 數字會被包成 node。但在 node system 裡，能用 node 就用 node，鏈才不會被 JS 的值切斷。

`EPSILON` 的用途最實際：擋除以 0。

```js
const bar = foo.div(max(angle, EPSILON));
```

shader 裡除以 0 不會丟例外，只會產生 `Inf` 或 `NaN`，然後那個像素變成一塊黑或一塊白，你得花半小時才找到是哪一行。分母只要有可能是 0，就先包一層 `max(x, EPSILON)`。

## 為什麼 time 不用自己更新

`time` 嚴格說不是 math node，但幾乎所有會動的公式都從它開始。它裝的是「開始 render 到現在的秒數」，而且**自己會更新**——不用宣告 uniform，不用在 tick 裡加。

```js
material.colorNode = time.sin();
```

`sin()` 回 [-1, 1]，負的部分會被截成黑色，所以看起來只亮一半的時間。要 [0, 1] 有兩種寫法：

```js
material.colorNode = time.sin().mul(0.5).add(0.5);
material.colorNode = time.sin().remap(-1, 1, 0, 1); // 同一件事，意圖更清楚
```

`remap(inMin, inMax, outMin, outMax)` 就是把一段區間映到另一段。範圍換算用它，比手算 `mul` / `add` 好讀得多。

還有一個 `deltaTime`，裝的是距離上一幀過了幾秒。這一課用不到，但之後做 GPU 驅動的動畫（粒子自己往前推一步）就會需要它——那時候的「上一幀狀態」存在 GPU 裡，只能靠 `deltaTime` 往前積分。

## 為什麼 hash() 和 rand() 並存

兩個都是偽亂數，都回 0~1，差別在吃什麼、怎麼算。

`hash()` 吃一個數。文件上寫 float，但它進去第一件事就是 `toUint()`，所以實際上是整數 hash：

```js
const pattern = hash(uv().x.mul(100));
material.colorNode = vec3(pattern);
```

`uv().x` 是 0~1，乘 100 再被截成整數，於是得到 100 條各自一個隨機灰階的直條。乘的那個數就是條紋的密度。

`rand()` 吃一個 vec2：

```js
const pattern = rand(uv());
material.colorNode = vec3(pattern);
```

`uv()` 是在 fragment 之間內插的連續值，所以每個 fragment 都拿到不同的輸入，結果是一片會閃的雜訊。想要穩定的圖樣，就先把輸入切成格子：

```js
const pattern = rand(uv().mul(100).floor());
material.colorNode = vec3(pattern);
```

`floor()` 之後同一格內的 fragment 拿到同一個輸入，一格就是一個顏色。**這是 shader 裡最常用的一招：連續的座標先量化，隨機才會「黏」在幾何上而不是黏在像素上。**

看 three.js 的實作就知道兩者不是同一套東西：`hash()` 是 PCG 那類的整數位元運算，`rand()` 是經典的 `fract(sin(...).mul(43758.5453))` 三角函數 hash。功能重疊、實作不同，課程也提醒這一塊近期可能會被重構，名字有機會變。

## 為什麼 noise 都叫 mx_

Perlin 那一家不用自己抄 GLSL，TSL 已經內建，前綴是 `mx_`。「mx」是 materialX——本來是 three.js 的 addon，現在整包併進 TSL 了。

```js
const noise = mx_noise_float(uv().mul(vec2(50, 10)));
material.colorNode = vec3(noise);
```

`uv().mul(vec2(50, 10))` 是在兩個軸上用不同的頻率取樣，所以圖樣被拉長。這個縮放係數就是 noise 的「頻率」，調它比換 noise 函式有用得多。

輸入的維度是自由的。`uv()` 是 vec2，換成 vec3 一樣收：

```js
const noise = mx_noise_float(positionWorld.mul(4));
material.colorNode = vec3(noise);
```

用 `positionWorld` 的意思是：圖樣長在**場景空間**裡，而不是長在表面上。mesh 靜止時看不出差別，一動起來就會發現顏色像是固定在空氣中、被 mesh 掃過去。

輸出的維度也可以換。`mx_noise_vec3()` 一次給三個獨立的 noise：

```js
const noise = mx_noise_vec3(positionWorld.mul(10));
material.colorNode = noise;
```

拿它當顏色不太真實，當**方向**卻很好用：三個分量湊成一個 vec3，就是一個平滑亂流的向量場，之後拿來推粒子（煙、火花）就是這個東西。

## 為什麼扭要加 positionLocal.y

這是這一課最值得留下的一段。先取一個角度，最簡單的版本就是 `time`：

```js
const angle = time;
const newXZ = rotate(positionLocal.xz, angle);
material.positionNode = vec3(newXZ.x, positionLocal.y, newXZ.y);
```

繞 y 軸轉，動到的是 x 和 z，所以先 swizzle 出 `positionLocal.xz`，轉完再重組。注意 `newXZ` 是 vec2，第三格要填的是 `newXZ.y` 不是 `.z`。

問題是這樣做完全沒意思：每個頂點拿到同一個 angle，整塊一起轉，跟直接改 `mesh.rotation.y` 一模一樣，還多繞了一圈。

差別只在一行：

```js
const angle = time.add(positionLocal.y).sin();
```

`positionLocal.y` 是**每個頂點不一樣**的值。加進去之後，高度不同的頂點就拿到不同的 angle，於是各轉各的——這才是扭。整段的重點就是這件事：GPU 上的算式是每個頂點各跑一次，公式裡只要混進一個逐頂點的量，效果就從「移動物件」變成「變形物件」。

外面包 `sin()` 是讓它來回擺盪而不是一直轉下去，順便把角度壓進 [-1, 1]。demo 的 slider 調的就是 `positionLocal.y` 的權重：0 退化成整塊一起晃，愈大扭得愈密。

拆開再組回去確實囉唆。課程說後面有更省事的寫法，這裡先照這個做，因為它把「哪個分量被動到」寫得最清楚。

## 用例

- **要一個會動的值**：`time`，不用自己開 uniform。要範圍就 `.remap(-1, 1, 0, 1)`。
- **分母可能是 0**：`.div(max(x, EPSILON))`，別等到畫面出現黑塊才回頭找。
- **要穩定的隨機格子**：`rand(uv().mul(n).floor())`。忘了 `floor()` 就會得到一片會閃的雜訊。
- **要條紋**：`hash()` 配一個軸，`hash(uv().x.mul(n))`。
- **要有機的圖樣**：`mx_noise_float()`，先調輸入的縮放係數再說。
- **要圖樣固定在場景裡**：輸入用 `positionWorld`，mesh 移動時圖樣不跟著走。
- **要一個亂流向量場**：`mx_noise_vec3()`，之後推粒子用。
- **要變形而不是移動**：在 angle / offset 的公式裡混一個逐頂點的量（`positionLocal.y`、`uv().x`），再寫進 `positionNode`。
- **懷疑型別被轉錯**：把兩個參數對調試試，或丟進 TSL Editor 看生成的 shader。

## Gotchas

- **`0.25.add(0.5)` 不成立**。JS 數字沒有 node 的方法，鏈的第一個必須是 node（`float(0.25)`）或改用 `add(0.25, 0.5)`。
- **型別跟著第一個參數走**。`int(1).add(float(0.3))` 是 1，小數被吃掉了，而且不會有任何警告。
- **shader 裡除以 0 不會報錯**。它安靜地產生 `Inf` / `NaN`，變成一塊黑或一塊白。分母先包 `max(x, EPSILON)`。
- **`sin()` 的負半邊看起來是黑的**。不是沒在動，是被截掉了。要看全程就先 remap 到 [0, 1]。
- **`rand(uv())` 會閃**。`uv()` 在 fragment 之間內插，每個像素輸入都不同。要穩定就先 `.floor()`。
- **`hash()` 收的是「會被轉成整數」的值**。傳 0~1 的 `uv().x` 進去全部變 0，整片同一個顏色；要先乘一個夠大的數。
- **`rotate()` 的第二個參數維度跟第一個綁在一起**。傳 vec2 就給一個 float 角度（內部走 mat2）；傳 vec3 就要給一個 vec3 的 Euler（內部是三個 mat4 相乘）。傳錯不會有好結果。
- **`rotate(positionLocal.xz, ...)` 回的是 vec2**。重組時第三格是 `newXZ.y`，不是 `newXZ.z`——後者根本不存在。
- **`positionNode` 動了頂點，normal 不會跟著動**。這一課看不出來是因為在看 noise 顏色；等要正確的光影時得另外處理。
- **shadow 會跟著 `positionNode` 走，raycaster 不會**。shadow pass 重用同一個 `positionNode`（要拆開就設 `castShadowPositionNode`）；但 raycast、bounding box、physics 都在 CPU 上算，完全不知道 GPU 把頂點搬去哪了。
- **R3F 寫法**：換 `colorNode` 等於換一支 shader，demo 用 `key={pattern}` 讓 material 重新掛載。但 slider 不能這樣做——每動一格就重編一次 shader 會卡死，所以 twist 走 `uniform()`（第 7 課的東西），`onChange` 裡直接改 `.value`，material 不重掛、shader 不重編。`time` 由 renderer 自己更新，不需要 `useFrame`。
